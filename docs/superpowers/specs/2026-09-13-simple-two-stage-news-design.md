# 무료 뉴스 단순 두 단계 처리 SPEC

## 목표
무료 OpenRouter만 사용해 5분마다 새 뉴스를 확인하고 중요한 새 속보를 빠르게 제공한다. 전량 처리/영속 기사 대기열은 만들지 않는다. 사용자 승인: 현재 모델 SPEC/검토, Luna IMPLEMENT, 검증 후 현재 브랜치 커밋/푸시. 서버 배포·PM2·실제 API/DB/푸시알림 호출은 하지 않는다.

## 변경 대상
GNews 운영/dry-run selector와 worker, llm_helper 요청 옵션, 기존 openrouter_budget 기본 한도, 관련 오프라인 테스트/README/조사 보고서. 기존 뉴스 검증 규칙·DB 공개 스키마·수집 피드/주기는 유지한다. 필요하면 단순한 news_pipeline.py로 새 두 단계 흐름을 분리하고 기존 news_selector의 검증/정규화/중복 함수를 재사용한다. 기존 단일 단계 selector는 레거시 호환용으로 남겨도 되나 운영/dry-run은 새 경로만 사용한다.

## 동작 / 설계
1. 회차당 현재 수집 결과만 처리한다. 동일 URL/DB 저장 URL/정상 평가 이력을 먼저 제외한다. 최대100개 후보(초과 입력은 최신순100개)를 한 번 선별한다. 이전 pending/품질재시도 목록을 회차 사이에 누적하지 않는다. 평가 캐시는 기존처럼 최대5000 URL의 메모리 캐시를 쓴다. 기존 pending 필드를 호환용으로 남기더라도 회차 종료에 비우고 다음 수집 결과를 대신 처리하지 않는다.
2. 1차 AI는 제목·설명·출처·시각 및 최근 사건 문맥으로 신규성/경제적 관련성을 판단한다. 반환은 원본 기사 식별자·중요도7~10·category·news_type·짧은 한국어 selection_reason. 원본 전체 제목/본문/URL을 응답에 복사시키지 않는다. 선별 프롬프트에는 경제적 가치/제외/사건중복/중요도/카테고리 규칙만 포함하고 한국어 요약 작성 요구는 넣지 않는다. 기사 내용은 신뢰되지 않는 데이터라고 명시한다.
3. 식별자와 enum, 점수를 코드로 검증한다. 형식 또는 식별자 오류를 정상 탈락과 혼동하지 않는다. 정상 응답에서 선택되지 않은 후보와 규칙 필터 제외는 evaluated로 기록할 수 있다. 잘못된 응답은 한 번 재요청하거나 실패로 종료하고 해당 후보를 evaluated로 기록하지 않는다.
4. 유효 선택 기사를 중요도 내림차순, published_at 내림차순, 안정적인 원본 순서로 정렬한다. 동일 사건 중복은 1차 지침과 기존 코드 중복 로직을 가능한 범위에서 사용하고 저장 전 동일 사건 검사는 반드시 유지한다. 상위10개만 한 번 요약한다. 10개 초과/입력100개 초과로 생략한 기사는 evaluated로 표시하지 않는다. 별도 대기열 없이 재수집될 때 다시 후보가 된다.
5. 2차에는 선택된 실제 원문과 식별자만 전달해 title/content 작성에 집중시킨다. 중요도/category/news_type/선별이유 및 원본 URL·제목은 코드가 1차/원본에서 합친다. 2차가 다른 기사 ID를 반환하거나 점수/category를 임의 변경해도 신뢰하지 않는다. JSON 리스트를 로컬 파싱하고 기존 _decision_to_item 및 최근 사건 중복 검증을 적용한다. 숫자/한국어 품질 실패 기사는 저장하지 않고 evaluated도 표시하지 않는다. 정상 기사만 저장/알림한다. 별도의 AI 품질보정/JSON복구 프롬프트는 사용하지 않는다.
6. 모든 generator 호출은 HTTP 총1번만 시도(max_retries=1). 두 단계에 공통으로 추가1회만 허용: 일시 통신 오류/빈 응답/JSON·응답계약 오류 시 같은 단계를 다시 요청한다. 1차에서 추가기회를 사용하면2차에는 재시도 없음. 일일/일시429 및 예산 오류는 즉시 해당 흐름 종료, 즉시 재시도 없음. 개별 기사 문장 품질실패는 재요청하지 않고 정상 기사만 보존한다. 0후보=0,0선택=1,정상=2,최악=3 HTTP/회차. 기존 selector 내부 복구/worker 외부10건배치가 이 흐름을 반복시키지 않아야 한다.
7. 일일 무료 예산 기본990, 기존 SQLite 영속 예약·429 차단·5분 슬롯 분배는 유지한다. GNews 전용 추가3회/회차 안전 가드를 실제 HTTP 전에 적용하거나 단일-attempt generator+공통 retry1회 구조로 강제하고 post spy 통합테스트로 증명한다. 288회/UTC일 가정 기본576/최악864이며 990은 다른 helper 사용까지 포함한 별도 안전장치다. GNews 주/백업 설정은 free-router 또는 :free만 허용하고 유료 이름은 시작 전 명확히 거부한다. 유료로 자동 fallback 하지 않는다.
8. helper의 max_tokens=2000 하드코딩을 인자로 바꾼다. 단계별 response_format/max_tokens 전달 가능하게 한다. 초기 선별 출력8192, 요약 출력8192 토큰을 설정값으로 제공하고 GNEWS_SELECTION_MAX_TOKENS/GNEWS_SUMMARY_MAX_TOKENS로 양의 정수만 허용한다. 출력은 짧게 쓰도록 schema/프롬프트로 제한한다. 모델 자체 한도는 별개이며 실제 무료모델 품질/시간은 오프라인 검증으로 증명했다고 주장하지 않는다. 원격 기본한도/품질 검증은 실제API사용 없이 수행 불가라고 보고한다.
9. 실패한 기사/DB저장 실패/품질실패/우선순위 컷은 처리 완료 표시를 하지 않는다. 실패 기사 자체는 회차가 끝나면 메모리에서 버린다. 다시 수집되면 재평가, 재수집은 보장하지 않는다. DB중복 또는 정상 저장만 evaluated로 완료처리한다. 이미 저장 후 알림 실패는 저장을 되돌리지 않고 기존 로그만 유지한다. 알림 재전송/영속 요약캐시/작업상태시스템은 범위 밖.

## 제약 / 예외
무료 only, 비밀 값/환경파일 출력·커밋 금지. 키 공유/다른호스트 사용은 로컬예산이 알 수 없다. 선별누락·상위10건 컷·무료장애·재수집누락은 가능하다. 오래된 기사 작성3시간 필터는 유지한다. 실제 모델 품질이나5분내응답은 보장하지 않는다. 이번 SPEC이 이전900회/누적pending/AI품질보정 SPEC의 운영 설계를 대체한다. 공개DB/푸시 계약과 기존 결정적 품질검증은 유지한다.
