# OpenRouter 무료 요청 예산 SPEC

> **Superseded (2026-09-13):** 운영과 dry-run은 [단순 두 단계 뉴스 SPEC](2026-09-13-simple-two-stage-news-design.md)으로 전환되었다. 이 문서는 이전 영속 pending·품질보정 설계의 구현 이력과 조사 근거로만 보존한다.

## 목표
5분 수집 주기와 기존 요약 품질 검사를 유지하면서 무료 OpenRouter 실제 HTTP 시도 수를 제한하고 일일 한도 429 재시도 증폭을 차단한다. SPEC/조사는 현재 모델, IMPLEMENT는 사용자 지정 Luna가 수행한다. 서버 배포·PM2·실제 API 호출·커밋은 범위 밖이다.

## 변경 대상
`llm_helper.py`, 작은 요청 예산 모듈, `gnews_tracker.py`, 필요한 경우 `news_selector.py`, 관련 오프라인 테스트, README 및 조사 보고서. 비밀 값과 `.env`는 출력/수정/커밋하지 않는다.

## 동작 / 설계
- 현재 기본 수집은 5분마다 세계 25건, 격회 경제 3개 피드 각 25건이다. 기본 10건 배치로 중복·필터 제외 전 신규 후보 전량의 기본 요청은 하루 144*(10+3)=1,872회다. 936은 현재 배치 10 기준과 불일치한다. 외부 배치만 늘려도 selector 내부 10건 배치가 남으므로 해결되지 않는다.
- selector는 기본 생성, JSON 복구, 재선별, JSON 복구, 품질 보정까지 최대 generator 5회, GNews generator 각각 최대 HTTP 3회로 내부 배치당 최대 15회다. 계속된 HTTP 실패에는 None→ValueError→재선별로 최대 6회가 된다. 보류 작업량은 제한되지 않아 총량 상한은 현재 없다. 느린 사이클은 중첩되지 않으므로 288회/일은 300초 안에 끝나는 경우의 계산이다.
- 모든 무료 모델(`openrouter/free`, `:free`)의 `requests.post` 직전에 SQLite 트랜잭션으로 시도 수를 예약한다. 실패·HTTP 재시도·JSON 및 품질 보정도 동일 예산을 쓴다. helper를 사용하는 구 RSS/수동 스크립트에도 적용한다. 유료 모델은 무료 예산을 쓰지 않는다. 모델 기본값과 품질/배치 10은 유지한다.
- 기본 `OPENROUTER_FREE_DAILY_LIMIT=900`은 사용자가 제시한 high-balance/1,000회 환경을 대상으로 한다. 50회 계정은 45로 명시 설정해야 한다. 자동으로 계정 등급을 알아냈다고 주장하지 않는다. 공유 저장소 경로는 `OPENROUTER_BUDGET_PATH`, 기본 프로젝트 내 `.openrouter-budget.sqlite3`; DB/WAL/SHM는 gitignore에 포함한다. API 키나 키 해시는 저장하지 않는다. 프로젝트 전체에서 보수적으로 하나의 예산을 공유한다.
- UTC 날짜별 일일 상한 + 5분 슬롯별 상한을 적용한다. 슬롯 s의 허용량은 floor((s+1)*L/288)-floor(s*L/288). 미사용 슬롯 예산은 이월하지 않아 아침 소진을 방지한다. L=900이면 슬롯당 3 또는 4, L=45이면 0 또는 1이다. 재시작·같은 파일을 쓰는 다중 프로세스에도 상한 유지. 저장소 오류는 HTTP 없이 중단한다.
- 일일 429는 본문에 free-models-per-day 또는 openrouter_free_tier_daily가 있는 경우로 명확히 분류한다. 첫 응답 후 다음 UTC 자정과 유효한 Retry-After/리셋 헤더 중 더 늦은 시각까지 영속 차단한다. Remaining=0 단독으로 일일 한도라 단정하지 않는다. 기타 429도 같은 generator 내 즉시 재시도/모델 교체하지 않고 Retry-After(초/HTTP-date, 최소 60초; 없으면 5분)를 공유 차단으로 저장한다. 원문 응답/예외 대신 상태·분류·시도 수 등 안전한 메타데이터만 로그한다.
- 전용 RuntimeError 계열 예외로 예산/429 차단을 전파한다. worker는 해당 회차 남은 AI 배치를 중단하고 미처리 기사를 rejected/evaluated로 표시하지 않는다. 품질 보정 중 차단은 이미 검증된 기사 결과를 보존하고 미해결 기사를 보류하되 예산 차단을 품질 실패 횟수로 소모하지 않도록 한다. 일반 품질 실패 정책은 기존대로 유지한다.
- 오랜 미처리 기사로 지연/메모리가 계속 늘지 않도록 매 회차 pending에서 작성 후 3시간 지난 기사를 제거하며 `expired`에 집계한다. malformed 날짜는 안전하게 제외한다. 품질 기준 완화나 비AI 생성 요약은 추가하지 않는다.
- 실제 HTTP 시도·예산 잔여·차단 이유를 비밀 없이 관측할 수 있도록 한다. 큰 리팩터링과 별도 모델/유료 자동 fallback은 하지 않는다.

## 제약 / 예외
원격 서버의 실제 환경·계정 사용량·별도 호스트의 공유 키 사용은 로컬 코드만으로 확정할 수 없다. 다른 호스트/경로는 예산을 공유하지 않으며 100회 여유도 이를 보장하지 않는다. 무료로 모든 신규 기사를 5분 내 요약하거나 24시간 가용성을 보장할 수 없다. 900회는 품질 보정과 실패 포함 상한이며 품질을 유지하는 대신 처리량을 줄인다. 예산 도입 전 같은 날 사용한 요청은 DB가 모르므로 계정 리셋 이후 도입하거나 기존 사용량에 맞춰 운영해야 한다. dry-run도 실제 API 사용이며 검증에서 실행하지 않는다.

## 완료 조건
- 오프라인 테스트로 실제 post 수: 정상/일일429/일시429/JSON 복구/품질보정/다음 회차/재시작/공유 DB/UTC rollover/낮은 한도/DB 오류를 검증한다.
- 288 슬롯 모의 실행에서 기본 한도 최대 900, 낮은 한도 최대45, 슬롯 재진입에도 초과 불가. 신규 기사 없으면0. 실측 평균은 로그 없이 알 수 없다고 표시한다.
- 문법 검사와 `tests/` 관련 테스트 통과. 실제 API·DB·푸시·배포는 하지 않는다.
- 보고서에는 파이프라인, AI 사용 위치, 호출식, 변경 전후 best/average/worst 및 가정, 429 처리, 남은 위험과 유료 고정 모델을 통한 장기 방향을 기록한다.
