# 프론트엔드 전달용 프롬프트: 정책/규제 카테고리 지원

아래 내용을 프론트엔드 작업 대화에 그대로 전달하세요.

---

백엔드의 `breaking_news.category`에 새 값 `policy`가 추가됐습니다. 기존 DB 조회 구조와 실시간 구독, 알림 키, 중요도 의미는 그대로입니다. 프론트엔드에서 새 카테고리를 누락 없이 표시하고 필터링하도록 수정해 주세요.

작업 범위:

1. `app/live/page.tsx`의 카테고리 목록에 다음 항목을 추가합니다.

```typescript
{ id: "policy", label: "정책/규제" },
```

2. 기존 `market`, `indicator`, `geopolitics`, `corporate` 동작을 바꾸지 않습니다.
3. 최초 진입의 기본 선택, 전체/초기화 동작, 사용자의 개별 카테고리 선택·해제에 `policy`가 자연스럽게 포함되게 합니다.
4. 최초 Supabase 조회뿐 아니라 realtime insert로 들어온 `policy` 기사도 즉시 같은 필터와 정렬 규칙을 적용합니다.
5. 기사 카드와 공유 카드에서 `policy`가 누락되거나 오류를 내지 않게 하고, 사용자에게는 `정책/규제`로 표시합니다.
6. 과거 데이터에 알 수 없는 category 값이 있어도 페이지 전체가 깨지지 않도록 기존의 안전한 기본 표시를 유지하거나 추가합니다.
7. 긴급 속보와 주요 경제 소식의 구분은 오직 기존 `importance_score` 기준을 유지합니다. `policy`라는 이유만으로 긴급 속보로 표시하지 마세요.
8. 푸시 구독 키 `breaking_news`, `important_breaking_news`와 알림 설정 계약은 변경하지 마세요.
9. DB 컬럼, Supabase 쿼리 계약, Pulse 계약, 백엔드 코드는 변경하지 마세요.

검증 항목:

- 기본 선택 상태에서 `policy` 기사가 보이는지
- 전체 선택/초기화 후 `policy`가 다른 카테고리와 동일하게 복원되는지
- `policy`만 선택하거나 해제했을 때 수동 필터가 정확한지
- Supabase realtime insert로 추가된 `policy` 기사가 즉시 올바르게 표시되는지
- 기사 카드와 공유 카드가 `정책/규제`를 정상 렌더링하는지
- 알 수 없는 기존 category 값이 들어와도 화면이 깨지지 않는지
- 중요도 7~8은 주요 경제 소식, 9~10은 긴급 속보라는 기존 표시가 유지되는지
- 기존 푸시 구독 키와 알림 설정이 전혀 바뀌지 않았는지

변경 후 수정 파일, 실행한 검사/테스트, 남은 수동 확인 사항을 짧게 보고해 주세요.

---

배포는 이 프론트엔드 지원을 백엔드의 `policy` 출력보다 먼저 적용하거나 동시에 적용하는 것이 안전합니다.
